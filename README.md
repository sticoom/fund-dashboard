# 资金核对看板

每日上传加密资金报表 Excel，系统自动解密 → 解析公式 → 核对各子账户收支 → 验证余额平衡 → 看板展示。无历史存储，每次上传覆盖上一次。

## 功能

- 上传加密 Excel（.xlsx），自动解密并核对
- 按账户分组显示净收支（排除往来）和内部往来
- 自动汇率换算（外币 → 人民币），展示跨币种汇损
- 余额平衡验证：期初 + 收入 - 支出 = 期末
- 三级可折叠表格：总览 → 账户分组 → 交易明细
- 往来配对：自动匹配内部转账的收入方和支出方

## 技术栈

- **后端**: Python / FastAPI / openpyxl / msoffcrypto
- **前端**: React / TypeScript / Vite

## 核心逻辑详解

### 数据流

```
用户上传 .xlsx
    ↓
server.py [/api/upload]
    ↓
verify.py ← 核对引擎
    ├── parser.py      解密 + 解析子表交易
    ├── config.py      币种/列映射/关键词
    └── classifier.py  往来识别
    ↓
verification.json → 前端 fetch 读取
```

### 日报汇总的双区结构

这是整个核对引擎的基础。日报汇总 sheet 分为上下两区，通过公式关联：

```
┌─────────────────────────────────────────────────────────────┐
│ 上区 (rows 5 ~ 总计行-1)    → RMB 人民币值                  │
│   D=昨日余额(¥)  E=本日收款(¥)  F=本日付款(¥)  G=本日余额(¥) │
│                                                              │
│   外币账户:  =D{下区行}*$L${下区行}  (本币×汇率=RMB)        │
│   CNY账户:   直接 SUMIF 引用子表列                           │
├─────────────────────────────────────────────────────────────┤
│ 总计行: A列含"总计"                                          │
│   D=期初余额总计  G=期末余额总计  ← 权威数据源               │
├─────────────────────────────────────────────────────────────┤
│ 下区 (rows 总计行+1 ~ 末尾)  → 原始币种值 + 汇率            │
│   B=账户名  D=昨日余额(本币)  E=本日收款(本币)  F=本日付款   │
│   L=汇率 (1.0=CNY)                                           │
│   E/F列公式: SUMIF(子表!列, 日期, 子表!金额列)              │
└─────────────────────────────────────────────────────────────┘
```

核对链路：

```
子表交易明细 → SUMIF聚合(下区) → ×汇率(上区) → RMB值
     ↓              ↓                  ↓
  逐笔核对     本币金额核对       人民币金额核对
```

### 子表三种布局

| 布局 | 摘要列 | 收入 | 支出 | 适用场景 |
|------|--------|------|------|----------|
| 标准布局 | C（摘要） | E | F | 大部分子表 |
| Pingpong 布局 | E（备注/短分类）+ L（备注/详细描述），优先 L | F | G | 子表名含 `pingpong` / `光子易` / `虚拟信用卡` |
| 复合子账户布局 | 各子表头行的 C（摘要） | E | F | 如子公司公账-工商银行、深圳主体对公美元户 |

**Pingpong 摘要列选择规则**：E 列是短分类（如"广告"），L 列是详细描述（如"付：DELAMU-DELAMU-US广告费"）。逐行判断：L 列有内容则用 L，否则用 E。L 列目前可能为空，后续有收支时会补充。

**复合子账户处理**：一张物理 sheet 包含多个子账户（如"子公司公账-工商银行"包含多个招行子账户），每个子账户有独立的表头行（含"摘要"或"明细"字样）。解析时遇到表头行会重新检测列映射，并跳过该行（不是数据行）。

### 负值收支处理

某些账户存在退款、冲销等场景，支出列可能出现负值（如 `-4003.38 USD`）。系统处理原则：

- **后端**：支出金额保留原始符号，不做 `abs()` 转换。核对时用 `abs(a - b) < TOLERANCE` 比较差值，而非比较绝对值。
- **前端**：过滤条件使用 `Math.abs(value) > 0.01` 判断是否显示（负值也是有效数据），实际渲染的金额保持原始正负号。
- **不活跃账户过滤**：`abs(income) < 0.01 and abs(expense) < 0.01` 才跳过，避免负值账户被误判为无收支而跳过。

### 往来识别（两层检测）

- **Layer 1** 关键词匹配：`category` 或 `summary` 含"往来"或"利润提回" → 标记为内部转账
- **Layer 1.5** 疑似检测：分类为"投资收益"/"投资款"或摘要含"转入/转出/提回/划转"等 → 疑似往来（输出 warning）
- **Layer 2** 跨 sheet 金额配对：A sheet 支出 = B sheet 收入（同日同额）→ 自动识别为往来对
- 非 SUMIF 公式账户（直接引用如 `=子表!J6`）：如果公式层往来金额为 0，会从交易列表中检查是否有标记为往来的交易

### 币种与汇率

- 子表名含"美元"→ USD 等（`CURRENCY_MAP`），汇率=1.0 → CNY
- 无关键词时按下区 L 列汇率推断（如 `rate != 1.0` → 外币）
- 跨币种往来自动计算汇损

### 其他业务规则

- **总计行定位**：搜索 A 列含"总计"的行，D 列 = 期初余额，G 列 = 期末余额
- **日期来源**：以文件名日期为准，K2 单元格做交叉验证
- **期初余额**：直接读取总计行，不是各子表求和
- **日期过滤**：子表含多日交易，只取 `report_date` 当天
- **浮点容差**：`TOLERANCE = 0.5`，避免汇率连乘精度差异
- **复合子账户行范围**：从 SUMIF 公式中提取 `data_row_start`/`data_row_end`，只解析对应行范围的交易

## 注意点

### 1. Excel 公式必须双次读取

openpyxl 的 `data_only=True` 只返回缓存计算值，不返回公式文本。必须解密两次：

- `data_only=True` → 取单元格值（金额、汇率等）
- `data_only=False` → 取公式字符串（SUMIF、引用等）

### 2. 前端写入目录

生产模式下 FastAPI 从 `dist/data/` 托管静态文件，但开发模式从 `public/data/` 读取。`server.py` 同时写入两个目录。

### 3. 负值收支不要做 abs()

支出列的负值是合法的业务数据（退款、冲销）。后端和前端都应保留原始符号：

- 后端核对：`abs(calc - reported) < TOLERANCE`（比较差值绝对值）
- 前端过滤：`Math.abs(value) > 0.01`（判断是否有数据）
- 前端显示：直接渲染原始值

### 4. Pingpong 子表摘要列优先级

Pingpong 布局的子表有两个"备注"列：E（短分类）和 L（详细描述）。`_detect_columns()` 会记录 `remark_last`（最后一个备注列，即 L）。逐行判断：L 有内容则用 L，否则用 E。

### 5. 复合子账户的表头行检测

复合子账户的物理 sheet 中，子账户之间有独立的表头行（含"摘要"或"明细"）。解析时：
- 遇到含"摘要"/"明细"的行 → 重新检测列映射 + 跳过该行
- 每个子账户的 SUMIF 公式限定各自的行范围，通过 `_get_sumif_row_range` 提取

### 6. 不活跃账户过滤要兼容负值

判断账户是否有收支时，必须用 `abs()` 包裹：`abs(income) < 0.01 and abs(expense) < 0.01`。如果只写 `expense < 0.01`，则支出为负值的账户会被误判为"无收支"而跳过。

### 7. 生产环境部署

- Python >= 3.8（fastapi >= 0.100 要求）
- CentOS 7 自带 Python 3.6 无法运行，需安装 Miniconda
- 端口 8000 被旧进程占用时：`fuser -k 8000/tcp`

### 8. 前端首次加载需预置空 JSON

部署时确保 `dist/data/verification.json` 存在（即使是 `{"sheets": []}`），否则 fetch 404 → HTML 解析失败 → 白屏崩溃。

## 踩坑记录

### 1. abs() 导致负值支出核对失败
- **症状**：收入核对通过，支出核对不通过，但总额能对上
- **原因**：`verify.py` 对支出值做了 `abs()`，将退款/冲销的负值翻转成了正值；同时不活跃账户过滤 `expense < 0.01` 把负值账户整个跳过
- **解决**：移除 `abs()`，保留原始符号；过滤条件改为 `abs(expense) < 0.01`
- **验证日期**：2026-05-29

### 2. Pingpong 子表摘要列提取错误
- **症状**：Pingpong 子表的 summary 显示"广告"等短分类，而非"付：DELAMU-DELAMU-US广告费"等详细描述
- **原因**：Pingpong 布局有两个"备注"列（E 和 L），代码只取了第一个（E 列，短分类）
- **解决**：`_detect_columns()` 记录 `remark_last`（最后一个备注列 L），逐行优先取 L 列内容
- **验证日期**：2026-05-29

### 3. 复合子账户无摘要列
- **症状**：子公司公账-工商银行、深圳主体对公美元户的 summary 全部为空
- **原因**：第一个表头行没有 C=摘要，子账户各自的表头行才有。代码只检测了第一个表头行
- **解决**：遍历每行时检测"摘要"/"明细"表头行，动态更新列映射并跳过该行
- **验证日期**：2026-05-29

### 4. 前端过滤隐藏负值账户
- **症状**：领头羊-光子易信用卡有收支数据（支出为负值），但核对页面不显示该账户
- **原因**：前端 `realSheets` 过滤条件 `sh.real_expense_rmb > 0.01`，负值不满足条件
- **解决**：所有判断条件改为 `Math.abs(value) > 0.01`，负值也能通过过滤；实际渲染保持原始值
- **验证日期**：2026-05-29

### 5. Excel 公式只能用 data_only=False 读取文本
- **解决**：解密两次，分别用 `data_only=True` 和 `data_only=False` 打开

### 6. 复合子账户交易重复
- **症状**：pingpong沃尔玛收款 6 个子账户共享同一张 sheet，每个子账户显示全部交易
- **解决**：从 SUMIF 公式提取行范围，传入 `parse_sheet` 做行范围过滤
- **验证日期**：2026-05-28

### 7. 非 SUMIF 公式账户的往来检测遗漏
- **症状**：往来差额巨大，远超汇损金额
- **解决**：公式层往来金额为 0 时，从交易列表检查是否有往来标记
- **验证日期**：2026-05-28
